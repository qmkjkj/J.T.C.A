# J.T.C.A / J.T.C.G 量化分析工具

一个本地运行的黑色风格股票研究 Web 应用，同时提供 A 股平台 J.T.C.A 与港股平台 J.T.C.G，可在首页顶栏一键切换。它通过东方财富公开接口获取自选股行情、两年日线与新闻，必要时自动切换到腾讯财经或 Yahoo Finance；选定标的后，把最近一个月的行情、技术指标和新闻提交给模型，生成未来一个月的条件式研判。

## 功能

- **双平台切换**：首页顶栏的 J.T.C.A / J.T.C.G 分段按钮用于切换 A 股与港股。切换后品牌名、模型名、指数条、交易时段、搜索范围、候选池、自选清单与 AI 提示词都会同步切换；不同平台的自选清单分别保存在浏览器本地。
- **自选清单**：搜索代码或公司名，最多维护 12 只自选股；启动时不预选任何标的，需手动勾选（最多 5 只）后才开始拉取数据与研判。自选清单、自动选股、持仓列表与 AI 盯盘默认折叠，点击标题展开或收起。
- **实时行情**：当前报价、涨跌幅、市值、市盈率、日内高低、成交量，每 45 秒刷新一次。
- **开盘实时同步**：交易时段内（A 股 09:30–11:30、13:00–15:00；港股 09:30–12:00、13:00–16:00），今日逐笔分时每 5 秒刷新；日线视图的最后一根 K 线也会随最新报价、日内高低与成交量实时更新，并按最新收盘价重算 MA20 / MA50。
- **日线周期**：选中标的后自动拉取约两年前的完整日线，支持 今日 / 本周 / 近1月 / 三月 / 六月 / 今年 切换。今日与本周使用东方财富分时数据：今日为最新交易日的逐笔成交（精确到秒），本周为本周的 1 分钟时序（时间戳到秒）；近1月为最后一个交易日往前推一个月的滚动区间，三月及更长周期使用日线，按自然日历计算。
- **K 线与走势图**：K 线、收盘线、MA20 / MA50、成交量、20 日支撑 / 阻力、悬浮提示和数据表。
- **技术指标**：1 周至 2 年收益率、RSI14、30 日年化波动率、52 周区间位置、最大回撤、20 日支撑 / 阻力、量比、趋势判断。
- **近 30 天新闻**：按标的筛选、去重、加载更多，保留原文链接。
- **AI 研判**：市场状态、组合立场、置信度、主线主题、逐股多空观点、技术面 / 新闻面解读、支撑阻力、基准 / 乐观 / 悲观情景、催化剂、风险与观察项。
- **自动触发**：勾选变化后自动拉取数据并自动提交模型；也可手动“立即研判”或“重新研判”。
- **自动选股**：面板默认折叠，点击标题展开；在左侧输入最低入股资金（最低 200 元），AI 先从当前平台的内置候选池（A 股约 50 只 / 港股约 80 只）中筛选出 8 只候选，再自动拉取候选近一月的行情、技术指标与舆情，交给 AI 按整手规则给出最多 5 只股票的资金配置，并自动载入“组合情报”。港股按每只股票各自的每手股数计算一手成本。
- **账户登录**：注册 / 登录后才能访问行情与 AI 功能；会话保存在远端 MySQL，7 天有效，可随时退出。
- **资金概览**：行情指数条下方显示当前账户余额、当前持股价值、实时收益、今日收盘收益、本月收益与累计收益，数据每 60 秒刷新一次。余额由管理后台设置；“充值”“提现”按钮会提示联系客服（微信号 `CJTqmkjkj`）。
- **一键自动交易**：自动选股完成后，可按本次资金配置一键记录交易。后端按实时行情成交价计算成本并写入数据库，持仓收益随后按真实行情持续计算并回写。
- **自选入手**：勾选自选股并研判完成后，“研判完成”状态旁会出现“入手”按钮。弹窗中列出当前选中的自选股及最新价，可自行勾选标的、填写买入股数（A 股每手 100 股；港股按个股每手股数，须为整数倍），并实时显示本次买入金额、账户余额与成交后剩余；确认后按实时行情成交并刷新持仓，账户余额不足会拒绝提交。
- **持仓列表**：自动选股面板下方显示当前持仓，包括名称、代码、股数、现价、市值与浮动盈亏，随账户概览每 60 秒刷新。默认折叠，点击标题展开；点击某只持仓，中间“组合情报”区会显示该股票的行情、走势、技术指标与近 30 天新闻。
- **一键平仓与部分卖出**：进入持仓详情后，“持仓详情”状态旁会出现“一键平仓”按钮，以及股数输入框和“部分卖出”按钮。一键平仓按最新行情价卖出该股票在当前账户下的全部持仓（同一代码跨多笔交易合并计算）；部分卖出只能按整手交易，股数必须为该股票每手股数的整数倍（A 股 100 股，港股因股而异）且不超过当前持股数，按先进先出依次从多笔持仓中扣减，成交金额回到账户余额并记录已实现收益。
- **AI 盯盘**：左侧“AI 盯盘”面板默认折叠。开启后由后端常驻盯盘进程每 30 分钟自动读取当前持仓、最新行情、技术指标与新闻，交给 AI 输出“持有 / 部分抛出 / 全部平仓”结论，并按最新行情自动抛售，无需手动确认。面板中的投资策略滑块从“防御”到“激进”连续可调（0 防御、50 均衡、100 激进）；拖动滑块或重新开启会立即触发一次分析。AI 以短线交易为目标，优先在每个交易日锁定收益，不做长线持有。
- **模拟交易账号**：用户带有“模拟交易账号 / 真实交易账号”权限字段。模拟账号只能进行模拟交易，页面上会显示对应提示；管理员可在后台切换该权限。
- **会员分级**：普通用户、黄金VIP、白金VIP、钻石VIP 四级。顶栏欢迎词显示会员称谓；钻石VIP 附带流光渐变特效；后台可随时调整用户等级。
- **管理后台**：访问隐藏地址 `/qmkjkj` 查看用户、登录日志、选股记录、交易记录与统计概览；可创建、启用、停用、删除前台账户，调整会员等级、账户余额与模拟/真实账号类型。登录页不显示后台入口。
- **缓存**：行情 25 秒、新闻与组合数据 5 分钟、AI 结果 15 分钟，减少重复请求和 token 消耗。
- **响应式布局**：桌面三栏，移动端先自选、再图表、再 AI、最后新闻；无前端构建步骤。

.venv\Scripts\python.exe -m pip install --upgrade pip

## 配置

复制 `.env.example` 为 `.env`，填写：

```dotenv
DEEPSEEK_API_KEY=sk-your-key-here
DEEPSEEK_BASE_URL=https://api.deepseek.com
DEEPSEEK_MODEL=deepseek-flash
DEEPSEEK_REASONING_EFFORT=max
MAX_SELECTION=5

DB_HOST=127.0.0.1
DB_PORT=3306
DB_USER=gupiao
DB_PASSWORD=your-db-password
DB_NAME=gupiao

ADMIN_USERNAME=qmkjkj
ADMIN_PASSWORD=change-me
SESSION_TTL_HOURS=168
```

| 变量 | 说明 |
| --- | --- |
| `DEEPSEEK_API_KEY` | 必填。仅由后端读取，不会出现在前端代码或 API 响应中。 |
| `DEEPSEEK_BASE_URL` | DeepSeek 兼容接口地址，默认 `https://api.deepseek.com`。 |
| `DEEPSEEK_MODEL` | 模型名，默认 `deepseek-flash`。 |
| `DEEPSEEK_REASONING_EFFORT` | 推理强度，可选 `low` / `high` / `max`，默认 `max`。强度越高，推理 token 越多，耗时与费用也越高。 |
| `MAX_SELECTION` | 单次研判最多标的数，默认 5。 |
| `DB_HOST` / `DB_PORT` | 远端 MySQL 地址与端口。 |
| `DB_USER` / `DB_PASSWORD` | 数据库账号与密码，只写在 `.env`，不要提交或截图。 |
| `DB_NAME` | 数据库名，字符集建议 `utf8mb4`。启动时会自动创建 `users`、`sessions`、`login_logs`、`screen_runs`、`trades`、`trade_positions`、`trade_realized`、`ai_watch_settings` 八张表，并为旧表补齐新增字段。 |
| `ADMIN_USERNAME` / `ADMIN_PASSWORD` | 后台 `/qmkjkj` 的固定账号密码。**部署后务必修改默认值。** |
| `SESSION_TTL_HOURS` | 登录会话有效期，默认 168 小时（7 天）。 |

修改 `.env` 后必须重启服务才会生效。

### API Key 安全须知

- **这个 Key 曾在聊天中明文出现，请立即到 DeepSeek 控制台吊销并重新生成。** 新 Key 只写入本机 `.env`，不要发到聊天、截图或代码仓库。
- `.env` 已列入 `.gitignore`，不要把真实密钥写进 `.env.example`、`README.md`、前端文件或日志。
- 前端通过 `/api/config` 只能获知“是否已配置”，拿不到密钥本身；模型请求由后端发出。
- 若接口返回 `401`，表示 Key 无效或已吊销；返回 `402`，表示账户余额不足。

### 账户与后台安全须知

- 用户密码使用 PBKDF2-HMAC-SHA256（26 万次迭代、随机盐）存储，数据库只保存会话令牌的 SHA-256 摘要，不保存明文。
- 用户会话 Cookie 为 `HttpOnly` + `SameSite=Lax`，默认 7 天过期；后台使用独立的 `jt_admin_session` Cookie，不能代替前台会话。
- 同一 IP + 用户名连续 8 次登录失败会被限制 10 分钟，成功或失败都会写入 `login_logs`。
- 账户余额只能由后台管理员修改；前台“充值 / 提现”只是客服引导，不会改动数据库余额。
- 一键自动交易接口要求登录，按当前用户身份记录交易，并在数据库事务中校验余额，不能操作他人账户。
- 后台账号密码来自 `.env` 的 `ADMIN_USERNAME` / `ADMIN_PASSWORD`。**首次部署后请立即把默认密码 `qmkjkj` 改掉，并重启服务。**
- 数据库密码、后台密码只写在 `.env`，不要写进前端文件、README、日志或提交记录。
- 上线到公网时请启用 HTTPS，否则 Cookie 与密码会以明文经过网络。

## 数据源与降级逻辑

| 数据 | 首选 | 备用 |
| --- | --- | --- |
| 股票报价 | 东方财富 `push2.eastmoney.com`（A 股 / 港股） | 腾讯财经 `qt.gtimg.cn`，港股可再降级到 Yahoo Finance |
| 两年日线 | 东方财富 `push2his.eastmoney.com`（前复权） | Yahoo Finance（`yfinance`） |
| 分时 / 逐笔 | 东方财富 `trends2`（分钟）与 `details`（逐笔） | 无备用源，失败时提示稍后重试 |
| 新闻 | 东方财富资讯搜索 | 港股可降级到 Yahoo 系来源；A 股可回退到东方财富公告 |

应用优先使用东方财富接口；东方财富不可用时，报价自动切换到腾讯财经，历史行情尝试 Yahoo Finance。页面右上角会显示当前实际使用的来源。

限制：

- A 股代码支持 `600519.SS`、`000001.SZ` 这类带交易所后缀的写法，也可以直接输入 6 位代码，后端会自动补全后缀。
- 港股代码支持 `00700.HK`、`700.HK`、`00700` 和 `HK00700` 等写法，后端统一规范为 5 位代码（如 `00700.HK`）；港股指数使用 `^HSI`、`^HSCE`、`^HSTECH`。
- 分时数据覆盖 A 股与港股：今日为最新交易日的逐笔成交（秒级），本周为最近 5 个交易日的 1 分钟数据（秒位为 `00`）；公开接口不提供历史逐笔明细。
- 北交所代码（`.BJ`）的报价可以查询，但历史行情与新闻的稳定性取决于数据源。
- 报价为公开接口数据，可能存在延迟，不是交易所级实时逐笔行情。
- 东方财富历史行情使用前复权，与 Yahoo 的复权与成交量口径可能略有差异，页面会给出提示。
- 自动选股的股数与金额按最新价和每手股数估算，不含佣金、印花税等交易费用，实际成交以券商为准。A 股每手固定 100 股；港股每手股数因股票而异，候选池中的 `lot_size` 会被逐只采用。

## 自动研判流程

1. 勾选标的后，前端请求 `/api/portfolio`，为每只股票拉取两年日线、当前报价和最近 30 天新闻。
2. 数据就绪后，自动请求 `POST /api/analysis`。
3. 后端把以下内容写入提示词：
   - 当前报价、交易状态与数据来源；
   - RSI14、MA20/50/200、52 周区间、波动率、各周期收益、支撑阻力与趋势；
   - 最近 22 个交易日的 OHLCV；
   - 每只股票最多 10 条最近 30 天新闻（标题、时间、来源、摘要）；
   - 近一年日收益率相关性矩阵。
4. 模型返回严格 JSON，后端清洗、截断、校验后交给前端渲染。
5. 相同数据指纹的研判结果缓存 15 分钟；“重新研判”使用 `force` 跳过缓存，但不会重复拉取行情。

费用与耗时参考：3 只股票的一次研判，prompt 约 5,800 tokens；completion tokens 包含推理过程，`DEEPSEEK_REASONING_EFFORT=max` 时会明显高于最终 JSON 的长度，通常需要数十秒到数分钟。标的数量、新闻条数、推理强度和模型定价会直接影响费用，请留意账户余额。

## 账户资金与模拟交易

- **账户余额**：由管理员在后台“用户管理”中设置，新注册用户默认为 0。充值 / 提现为人工客服流程，前台按钮只显示客服微信 `CJTqmkjkj`。
- **收益口径**：
  - 当前持股价值：全部持仓按最新价计算的市值合计，不含已平仓部分。
  - 实时收益：全部持仓按最新价相对买入价计算的浮动收益，随行情每 60 秒刷新；只统计未平仓持仓，已落袋收益不计入。
  - 今日收盘收益：未平仓持仓按最新价相对上一交易日收盘价计算，加上今日平仓产生的已实现收益；当日买入的持仓按买入价计算。
  - 本月收益：未平仓持仓按最新价相对本月首个交易日前收盘价计算，加上本月平仓产生的已实现收益；本月买入的持仓按买入价计算。
  - 累计收益：未平仓持仓的浮动收益加上全部历史平仓的已实现收益。
  - 平仓时会把该笔已实现收益、对应的今日收益与本月收益写入 `trade_realized`，后续账户概览按交易日汇总，避免重复计算。
  - 自动交易记录写入 `trades` / `trade_positions`，每次读取账户概览时会刷新最新价、市值、收益并回写数据库。
- **一键自动交易**：只有完成一次自动选股后才能点击；后端按实时行情重新计算成交价与成本，余额不足会拒绝交易。成交后从账户余额扣除成本，交易类型由用户的“模拟交易账号 / 真实交易账号”权限决定。自选入手走同一接口，提交前会再次校验每手股数与账户余额。
- **一键平仓 / 部分卖出**：在持仓详情页触发，后端按最新行情价成交。一键平仓一次卖出该代码的全部持仓；部分卖出按输入股数从最早买入的持仓开始依次扣减，股数必须为该股票每手股数的整数倍（A 股 100 股，港股因股而异）；剩余不足一手的零股可通过一键平仓全部卖出。成交金额计入账户余额，并写入 `trade_realized`。若同一代码分散在多笔交易中会合并处理；某笔交易清空后状态改为 `closed`，仍有其他持仓的交易继续保留并按剩余持仓重算市值与收益。
- **AI 盯盘**：由用户手动开启，开关与策略写入数据库 `ai_watch_settings`。后端常驻守护线程每分钟扫描一次到期用户，对每个开启盯盘的用户每 30 分钟合并同一代码持仓（最多取市值最高的 12 只），拉取行情、指标与新闻后提交模型；模型返回持有、部分抛出或全部平仓三类结论，后端随即按最新行情自动卖出（部分卖出按该股票每手股数取整）。关闭浏览器页面后后台进程仍会继续盯盘；关闭开关即停止。
- **双平台共用账户（演示口径）**：港股平台沿用同一人民币账户、余额与持仓表，港股价格按行情原值直接扣减余额，页面金额仍以 `¥` 展示；不进行港币兑换，也不单独维护 HKD 钱包。该实现改动小、便于内部演示，但币种口径并不严谨，不应视为真实跨境结算。
- **说明**：本项目未接入真实券商，所谓“真实交易账号”仅表示权限类型，收益仍按公开行情模拟计算。若需要真实下单能力，需要另行对接券商接口并完成合规审查。

## 常见问题

**页面提示“无法连接本地服务”**  
确认 `start.bat` 窗口仍在运行，或访问 `/api/health` 检查服务。

**端口 8000 被占用**  
关闭已运行的 Python / uvicorn 进程后重试，或直接访问已运行的服务。

**行情正常但 AI 报错**  
检查 `.env` 中的 Key、余额和网络。页面会把 401 / 402 / 超时等错误直接显示出来。

**新闻为空**  
东方财富资讯或公告接口暂时不可用时，新闻可能为空；应用会继续使用行情数据研判，并降低置信度。

**数据日期不是今天**  
A 股休市、盘前或数据源延迟时，最新一根日线可能是上一个交易日；页面会显示数据截至日期。
